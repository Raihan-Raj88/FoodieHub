# FoodieHub — Stripe Test Mode Setup

The payment integration is fully implemented.
Two values in `backend/.env` need real Stripe test credentials before online payments activate.

---

## Step 1 — Get your Stripe test keys

1. Go to https://dashboard.stripe.com
2. Create a free account (or log in)
3. Make sure the toggle in the top-right says **"Test mode"** (should be ON by default for new accounts)
4. Open **Developers → API keys**
5. Copy the two values shown:

| Key | Looks like | Paste into |
|---|---|---|
| Publishable key | `pk_test_51...` | *(not needed — backend only)* |
| Secret key | `sk_test_51...` | `STRIPE_SECRET_KEY` in `backend/.env` |

---

## Step 2 — Update backend/.env

Open `backend/.env` and replace the two placeholder lines:

```
# BEFORE (placeholders — Stripe disabled)
STRIPE_SECRET_KEY=sk_test_your_stripe_secret_key
STRIPE_WEBHOOK_SECRET=whsec_your_webhook_secret

# AFTER (real test credentials — Stripe enabled)
STRIPE_SECRET_KEY=sk_test_51XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
STRIPE_WEBHOOK_SECRET=whsec_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

Leave every other line exactly as-is.

---

## Step 3 — Get the Webhook Secret (for local development)

The webhook secret is generated by the **Stripe CLI**, not the dashboard.
It is different every time you start the CLI listener.

### Install Stripe CLI

**Windows (Chocolatey):**
```
choco install stripe-cli
```

**Windows (Scoop):**
```
scoop install stripe
```

**Windows (direct download):**
Download the zip from https://github.com/stripe/stripe-cli/releases/latest
Extract `stripe.exe` and add it to your PATH, or place it in the project root.

### Log in to Stripe CLI

```
stripe login
```

A browser window opens. Approve access in your Stripe dashboard.

### Start the webhook listener

Run this in a **separate terminal** (keep it open while testing):

```
stripe listen --forward-to http://localhost:5000/api/payments/webhook
```

The CLI will print something like:

```
> Ready! Your webhook signing secret is whsec_a1b2c3d4e5f6...
```

Copy that `whsec_...` value and paste it as `STRIPE_WEBHOOK_SECRET` in `backend/.env`.

---

## Step 4 — Restart the backend

After updating `.env`, restart the backend server so the new keys load:

```
cd backend
npm run dev
```

Verify Stripe is now active:
```
curl http://localhost:5000/api/payments/config
```
Expected: `{"success":true,"stripeEnabled":true}`

## Step 5 — Test a payment

1. Start the frontend: `cd frontend && npm run dev`
2. Open http://localhost:5173
3. Add items to cart → Checkout
4. The **Online Payment** option will now be clickable
5. Click **Pay with Stripe**
6. On Stripe's hosted checkout page use the test card:

| Field | Value |
|---|---|
| Card number | `4242 4242 4242 4242` |
| Expiry | Any future date (e.g. `12/34`) |
| CVC | Any 3 digits (e.g. `123`) |
| Name / ZIP | Anything |

7. Click **Pay** — you will be redirected to `/payment/success`
8. The order status changes to `confirmed` and payment status to `paid`

### Test a declined card

| Scenario | Card number |
|---|---|
| Generic decline | `4000 0000 0000 0002` |
| Insufficient funds | `4000 0000 0000 9995` |
| 3D Secure required | `4000 0025 0000 3155` |

---

## Step 6 — Test payment cancellation

1. Start a Stripe checkout
2. Click the **← Back** arrow on the Stripe page (do not enter card details)
3. You are redirected to `/payment/cancel`
4. The order remains saved with `paymentStatus: pending` — it is not deleted

---

## Step 7 — Verify webhook delivery (optional)

While `stripe listen` is running, complete a test payment.
The CLI terminal will show:

```
2024-xx-xx  POST http://localhost:5000/api/payments/webhook  [200] checkout.session.completed
```

A `200` confirms the webhook was received, signature was verified, and the order was updated in MongoDB.

## What each environment variable does

| Variable | Purpose | Required for |
|---|---|---|
| `STRIPE_SECRET_KEY` | Authenticates your backend to Stripe's API. Used to create Checkout Sessions and retrieve session status. Never sent to the browser. | Creating sessions, verifying payments |
| `STRIPE_WEBHOOK_SECRET` | Verifies that webhook POST requests genuinely came from Stripe, not from an attacker. Each `stripe listen` session generates a new one. | Webhook signature validation |
| `FRONTEND_URL` | The base URL Stripe redirects to after payment. Already set to `http://localhost:5173`. | success_url and cancel_url in the session |
